# V2code 本地 Magpie 插件

在同一 `v2code` 供应商中调用模型并显示官网账户余额。无 npm 依赖、无常驻额外后台服务；默认不保存官网密码，仅在登录页勾选后才保存并用于自动续登（见下文）。

## 安装与登录

```sh
magpie plugin add https://github.com/sijinhui/magpie-v2code
```

1. 运行上面的命令从 GitHub 安装；也可在 Magpie → 插件 → 添加插件中填写仓库地址。开发时可选择本地文件夹，或运行 `magpie plugin add <本文件夹的绝对路径>`。
2. 在插件供应商 V2code 中选择“官网账号密码登录 → 手动选择已有 Key（推荐）”。
3. Magpie 打开临时本机登录页。输入官网账号密码，登录后在下拉列表中按 **名称、分组和尾号** 选择一个已有 Key，不需要复制、粘贴或输入模型 Key。
4. 点击“使用选中的 Key”，等待 Magpie 完成登录。本机页面会关闭监听，之后可关闭浏览器标签页。插件保存选中的模型 Key、官网登录 JWT、用户 ID 与 Key 的标识/名称/分组；仅当勾选“保存官网账号密码”时才额外保存账号和密码（见下方“可选：保存官网账号密码并自动续登”）。未选中的 Key 不保存。
5. 仍保留“模型 API Key + 官网登录令牌”手动导入和“仅模型 API Key”两种备用方式。后者余额显示未配置，不伪造为零。

账号密码方式使用已有 Key，不会创建、删除、修改 Key。列表只包含启用、未过期且不限额或仍有可用额度的 Key；超过 2000 条、列表读取过程中变化或无法确认完整 Key 时明确报错，不默认挑选第一把。提交选择时再查询一次列表，防止使用刚被停用、过期或更换的 Key。遇到验证码或官网拒绝登录时，不尝试绕过或反复重试，可改用手动导入方式。

本机登录页仅监听 `127.0.0.1` 随机端口，带随机路径、表单 CSRF 校验和严格来源校验；密码输入框为掩码，页面不缓存、不展示完整 Key/JWT，5 分钟超时或取消后关闭。不要在不属于本机地址的仿冒页输入账号密码。插件代理或本机其他恶意程序的风险不由本页面解决。

取得官网令牌：自己在 `https://www.v2code.ai` 登录，打开浏览器开发者工具 → 网络 → 查看 `app_admin/user/data` 请求的 `Authorization` 请求头；复制其中的 `eyJ…`，不加 `Bearer `。也可在应用 → 本地存储 → `https://www.v2code.ai` 中复制 `token`。不需要提供密码、Cookie 或完整 HAR 文件。

**JWT、模型 API Key 和（勾选保存时）官网账号密码都是敏感凭据。** 不要发到聊天、截图、工单、源码或 Git 仓库。JWT 是官网账号登录态，不保证只有余额读取权限。Magpie 将它们保存在账号 metadata，与 API Key 一样写入本机私密账号文件；这不等于加密保险箱。插件不扫描浏览器、不自动提取令牌、不读取其他供应商账号。遇到令牌失效，对 Magpie 中的同一账号“重新登录”即可重新认证、选择 Key；也可手动导入新令牌。默认不保存密码；勾选后才按下方“可选：保存官网账号密码并自动续登”的条件保存与续登。

## 可选：保存官网账号密码并自动续登

官网登录令牌（JWT）会过期，过期后余额和今日用量无法读取。本机登录页提供一个**默认不勾选**的选项“保存官网账号密码，在官网令牌过期时自动重新登录”。

- **不勾选**：与之前一致，不保存账号和密码，令牌过期后需要在 Magpie 中手动重新登录。
- **勾选**：账号和密码以**明文**写入 Magpie 的本机账号文件（`webUsername`、`webPassword`）。该文件是本机私密文件，不是加密保险箱，任何能读取它的程序都能获得官网密码；官网密码的权限大于模型 Key。不需要时请重新登录并不勾选，覆盖保存的凭据。
- **续登时机**：令牌已过期或将在 1 分钟内过期，或余额接口返回 401/403/状态 101 时，插件向 `https://www.v2code.ai/api/v1/app_admin/user/login` 登录一次，再重试一次余额查询。新令牌只缓存在内存，不回写账号文件；重启后会再次登录。
- **边界**：同账号并发读取共用一次登录；登录失败（如验证码、风控、二次验证、密码变更）后 5 分钟内不再重试，并提示手动重新登录；取消的请求不计入失败。续登得到的用户 ID 必须与账号一致，否则拒绝。账号密码只发往官网登录地址，不发给余额接口、模型接口或模型列表。
- 续登只影响余额和今日用量，**不影响模型 Key 和模型调用**。

## 从现有自定义供应商迁移

不要直接删除原供应商或修改路由。先备份，再将原模型 Key 登录到插件账号；确认余额和端点后，原 `providers.json` 中 `id: "v2code"` 的条目仅保留名称、图标、已选模型、路由偏好等非凭据设置，移除旧 `key`、`responses`、`anthropic`、`baseAPI` 等模型连接设置，由插件接管。保留所有 `groups` 及其他供应商原样。

在旧自定义供应商仍带 Key/端点时，Magpie 可能把插件显示为 `v2code-plugin`，不能因此把路由也改成新 ID。正式迁移应在账号登录和备份完成后进行，并停用再启用本插件，使正在运行的网关加载新账号。不要给插件启用只支持直接 Key 供应商的 `nativeCompaction`。

## 端点与行为

- 供应商 ID 固定为 `v2code`。GPT 使用 `https://dev.v2code.ai/v1/responses`；Claude 使用 `https://jp.v2code.ai/v1/messages`，支持同节点的 `/v1/messages/count_tokens`。
- 官网账号认证为 `POST https://www.v2code.ai/api/v1/app_admin/user/login`，JSON 为 `username`、`password`；只在当前登录请求中使用密码。`data.jwt_token` 和 `data.user_id` 交叉核对后用于官网接口。Key 列表为 `POST https://www.v2code.ai/api/v1/app_admin/token/list`，JSON 为 `page`、`page_size`，解析 `data.rows`、`data.total`。官网原始 Key 无前缀时按官网复制行为补 `sk-`；已有前缀不重复补。
- 模型列表从 `GET https://dev.v2code.ai/v1/models` 读取，最终只列出账号实际返回的 GPT/Claude 模型。其他协议族不猜测端点、不显示。
- `models.mjs` 是 2026-11-13 本机 models.dev 缓存中现有两个已选模型的能力快照，不保证中转站支持全部能力。其他模型沿用 Magpie 已有元数据，未知能力不虚构。不声明未经验证的价格。
- 余额使用 `POST https://www.v2code.ai/api/v1/app_admin/user/data`，请求头 `Authorization: <JWT>`（无 Bearer 前缀）、`User-Id: <ID>`。请求体为 Asia/Shanghai 当天的 `start_time`、`end_time`（Unix 秒）和 `default_time: "day"`。
- `data.quota` 为剩余，`data.used_quota` 为累计已用；历史总额与官网一致按两者之和显示。账户余额按预付钱包处理，不伪造每月限额、重置时间或过期时间。显示单位为站内额度，不声称是可提现美元。
- 概览的“今日用量”读取同一回复的 `data.statistics_quota`，即官网概览所选时间范围的“统计额度”，不使用历史累计值 `used_quota`。插件固定查询 Asia/Shanghai 当天 00:00:00–23:59:59，刷新时重新计算日期；官网按浏览器本地时区选日期，浏览器不在上海时区时两者范围可能不同。此项为整个官网账号的消耗，包含其他 Key/客户端使用，不是仅经过 Magpie 或当前 Key 的消耗。
- 今日统计复用余额请求，不新增官网请求。有效零值正常显示 `今日已用 0.00 额度`；统计字段缺失、非数值或为负时显示“今日用量暂不可用”，仍保留余额和累计使用，不把未知用量当零。未配置官网认证的仅模型 Key 登录方式仍无法查询余额及今日用量。
- 余额错误不清除模型登录态；字段缺失、限流、验证页等显示错误，不把未知余额当零。仅余额验证，不进行模型生成或充值。
- 模型请求只放行上述固定 HTTPS 目标和 POST 接口，不跟随重定向；移除 Cookie、官网 User-Id、旧鉴权和 Magpie 内部头，重新设置模型 Key。官网 JWT 只用于官网余额请求，绝不附加到模型请求。所有出站请求显式禁用隐式凭据。
- 请求已取消或读取账号期间被取消时，不再发起模型请求；已取消的官网/模型列表请求也不再调用上游。浏览器登录取消或超时后，迟到的登录、Key 列表响应不能继续后续步骤或完成账号选择。
- 官网登录、Key 列表、余额及模型列表等 JSON 接口的响应体上限为 1 MiB，单次请求超时 20 秒。这些限制不适用于模型生成：模型流式请求原样透传，不缓冲回复，不改工具字段，不修改模型 ID。
- 模型连接原始异常及其 `cause`、下游取消和上游断流原样传给宿主；不自动重试模型生成。插件不伪造 token 数、流式事件或速度计时，不能保证每条请求都有可测速度。
- 模型列表的空白或无效名称回退为已有有效名称或模型 ID，只使用已有模型的自身属性，不把继承属性当作模型配置。

## 排查 `an empty reply ... ended with nothing in it`

此错误表示 Magpie 未取得可用的模型输出，不等同于插件鉴权失败，也不能仅凭错误文字认定插件丢失响应。插件的模型 fetch 只校验目标、设置鉴权并返回原始 Response；Messages → Responses 的协议转换和输出解析由宿主负责。

1. 在 Magpie 请求日志中区分 `502 + empty reply`、`499 + agent_canceled` 与成功的 `200`。路由分类器在 8 秒后取消，与模型完成后空输出是两种问题；不要通过修改官网接口的 20 秒超时处理它们。
2. 查看同一路由的各次尝试。如果同一输入在多个渠道、同一模型上均为空，优先检查共同的会话形态、模型行为和宿主转换，而不是先更换 V2code Key。输出 token 数非零不代表存在可见文本或工具调用，也不是请求的输出预算。
3. 进一步定位需要脱敏的上游 HTTP 状态、request-id、终止事件类型、`response.status`、`error.code`、`incomplete_details.reason`、output item 类型与数量，以及请求的输出预算/推理配置。区分真实空 output、仅工具调用、仅 reasoning 和解析不兼容；不要公开 Key、JWT、原始提示词或工具参数。
4. 若原始 output 为空，保留失败供宿主回退或人工重试；不伪造占位文本、不自动重试已计费的生成。若 output 实际含文本/工具调用但宿主未识别，需使用脱敏事件样本检查宿主 SDK/协议适配，再做定向修复。

离线响应测试覆盖原字节透传、工具输出、空完成、仅终止事件带文本、推理输出、失败/截断事件和取消。它们不证明宿主协议转换正确，也不代表真实上游空响应故障已修复。

## 验证

`npm test` 运行 Node.js 测试，需要 Node.js 22.15+。测试仅使用虚构账号、Key/JWT 和模拟官网接口，不读取真实账号；本机登录页测试需要允许回环网络。`npm run test:host` 可通过环境变量指定本机 Magpie/Bun，在隔离目录中测试真实宿主。验证记录及变量设置见 `VALIDATION.md`。

接口依据：2026-11-13 官网公开前端代码、已成功的官网余额请求，以及 Magpie 0.1.4066 插件 host。站点私有接口可能变更，需相应维护。使用本地目录安装时，插件按目录原地加载，请勿移动或删除已安装目录。
